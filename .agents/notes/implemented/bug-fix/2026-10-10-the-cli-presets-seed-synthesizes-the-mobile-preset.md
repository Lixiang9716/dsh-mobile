# Agent Note: the CLI presets seed synthesizes the mobile preset

Status: implemented

## Problem

The settings-surfaces CLI leg (runtime/dsh/ci/run-settings-surfaces-e2e.sh →
runtime/dsh/scenario/settings-surfaces.js) has been red-by-construction on
mac/linux dev machines since the deployment default became `mobile`
(upstream/boot.js `AGENT_PRESETS_DEFAULT`, flipped when the ios
interactive-circle work landed the preset on the devices, #198/#422): the
scenario demands `agentPresets/list` mark a default row whose id is `mobile`
(settings-surfaces.js `DEFAULT_PRESET`), but the seed its runner posts —
runtime/dsh/scenario/agent-presets-probe-seed.js, generated by
runtime/dsh/ci/gen-presets-seed.py — carried only the four upstream-shipped
presets (cordis/minimal/ptc/standard). The vendored presets package ships no
mobile preset: the devices synthesize it at stage time, each stager copying
runtime/dsh/presets-mobile/mobile/{preset.yml,agent.cordis.yml} into the
staged agent-presets copy at the presets/mobile/ rel (vendor-official.sh,
gen_bundle_resources.py; android deliberately stages the four shipped ones
only — test/panel/preset-health.test.js pins that). The CLI twin generator
never learned the synthesis, so the roster's default row was `undefined` and
the demand failed before any event matched. Compounding the rot: nobody
noticed because NO CI job runs the leg — `build/build.sh test core` is a
local-only surface (.github/workflows/* never invoke
run-settings-surfaces-e2e.sh), and the committed seed had drifted from the
vendored pin besides (39 rows vs the current 60-package closure).

## Decision

gen-presets-seed.py now synthesizes the mobile preset into the CLI seed the
same way the device stagers stage it: the two files from our outboard
runtime/dsh/presets-mobile/mobile/ at the presets/mobile/ rel, byte-identical
(verified against the source; the vendored presets package itself stays
untouched, D6). The generator fail-louds when the source dir carries a file
the stagers do not stage (MOBILE_FILES), so the three runtimes' seed shape
cannot silently diverge; it also emits POSIX VFS keys on every platform
(`relative_to(...).as_posix()` — a raw Windows run used to mint backslash
keys the vendored discovery reads as single file names). The seed is
regenerated (72 rows: 10 presets-tree + mobile's 2 + 60 markers — the
pin-current regeneration the header mandates), and its two committed host
twins (harmony rawfile scenario/, android assets scenario/) are re-synced
byte-identical. The expected manifests (test/e2e/scenarios/
settings-surfaces.json + the runtime/dsh/ci mirror) and the runner receipt
text record the post-fix truth: roster standard/mobile/ptc/minimal/cordis
with default `mobile`, healthy 1 (minimal resolves whole over the 60-marker
seed), read = the PATCHED mobile doc (web-boot.js disables the
mobile-absent rows in every seed .yml at delivery; 11862 UTF-16 units),
presetRows 6 (minimal's flatten; broken presets answer rows: []).
test/panel/cli-preset-seed.test.js replicates the demand as pure functions
over the generated seed — discovery order, the seed patch
(preset-mobile-rows.js, which cannot load under node, is replicated
line-for-line), the marker-resolution health walk, and the manifest
agreement — so the panel gate (which DOES run on every PR and on Windows)
now catches the next drift of seed ↔ patch ↔ manifest.

## Alternatives considered

- Change the scenario's `DEFAULT_PRESET` back to a shipped preset. Rejected:
  it would test a deployment the products do not run — the device seats join
  the `mobile` default (that is what #422's user-facing boot wires), so the
  CLI proof must prove the same thing. P5's verdict stands: the seed needed
  the extension, not the test a weakening.
- Add presets/mobile/ to the vendored tree (or re-pin a patched
  agent-presets). Rejected: D6 — upstream bytes stay verbatim; the mobile doc
  is OUR outboard composition, which is exactly why it lives in
  presets-mobile/ and is staged in by each host's own mechanism.
- Hardcode the roster expectations in the panel test instead of deriving
  them from the seed. Rejected: a second copy of the truth would rot the
  same way the committed seed did; the test derives everything from the
  generated artifact + the vendored rules and only pins the manifest to
  match.
- Regenerate only the mobile rows and keep the stale 39-row seed. Rejected:
  the generator's output is a function of the vendored pin, and a half-
  regenerated artifact is exactly the silent drift this fix closes.

## Consequences

The settings-surfaces leg is expected green again on a mac/linux machine;
the derivation is machine-checked by the panel suite on every PR, but the
leg itself remains locally-run — wiring `build.sh test core` (or at least
this runner) into CI is the follow-up that would have caught this weeks ago
(filed as a finding on the PR).
