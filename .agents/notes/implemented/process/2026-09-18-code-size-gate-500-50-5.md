# Agent Note: code-size gate 500 50 5

Status: implemented

Superseded (AST part): see `2026-09-18-code-size-ast-upgrade.md` — tree-sitter spans replace the heuristic for TS/JS.

## Problem

Agent-written code (and humans under time pressure) drifts toward monster files, god functions,
and deep nesting. Reviewing those after the fact is expensive, and nothing in CI said "stop".
The project needed the limit enforced at commit time, not in review comments.

## Decision

A `code-size` hard gate (no `allowFailure`) now runs `tools/check-size.py` over every
git-tracked source file (TS/JS/JSX/TSX/Swift/Kotlin/Python):

- files <= 500 lines
- functions <= 50 lines (Python via `ast`, brace languages via signature heuristic + depth)
- indent <= 5 levels (per-file dominant indent unit; tabs count as one level)

Registered in `gates.json` `modes.all`; wired into pre-push and CI like every other gate.

## Alternatives considered

- **ESLint/ktlint/swiftlint per language**: precise, but four toolchains to install and pin
  before any source exists; a single cross-language heuristic buys 90% of the value at 5% of
  the setup, and per-language linters can still be added per-host later.
- **Review-only convention**: rejected — unenforceable promises violate `.gov/rules.md` rule 1
  (gates over prose).
- **Stricter AST-only checking for brace languages**: rejected for now — tree-sitter toolchains
  add install weight; the heuristic's known limits (template-literal interpolation) are
  documented in the script header and acceptable until real code says otherwise.

## Consequences

The heuristic may under/over-count a function in pathological brace-language files; when that
happens the code should be simplified (split the function), not the gate bypassed. Thresholds
live in one place (`tools/check-size.py` constants) — changing them is a decision that needs a
new note, not a quiet edit.
