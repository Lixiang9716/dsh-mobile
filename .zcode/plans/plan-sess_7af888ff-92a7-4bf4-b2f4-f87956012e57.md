# Mobile UI 重设计：新 Web Client「dsh-web-client-next」（参考 clarklevis/dsh-mobile）

## 结论（做什么）

新建一个自研 Web Client 插件 `presentation/web-client-next/`（id `dsh-web-client-next`），照搬 clarklevis/dsh-mobile 的设计语言与交互模式，挂在 iOS 的 SessionServe 座位上（与官方 dist 同一 `/api` + `WS /api/remote.mux` 平面），作为可选客户端（`-dsh-web-client dsh-web-client-next`），不动官方 dist 一根毫毛（D6）。Android/Harmony 挂载是后续 PR。

关键事实依据（已调研确认）：
- 现有 v0 客户端走的 `/ws` `session-projection@0` 是**只读投影**（发不了 prompt），所以新客户端必须走官方平面：`POST /api/<endpoint>`（session/list、session/create、session/prompt、session/cancel…）+ `WS /api/remote.mux`（journal 基线+增量帧 = 流式 token）。
- 官方 journal 词表（`turn/start|end`、`assistant/chunk`、`assistant/message`、`tool/*`、`agent/status`、`session/title`…）就是 clarklevis 渲染的那套（第三方子模块 `third-party/deepseek-harness/packages/sdk` 里已核实存在）；它的投影折叠逻辑（9 种 item：USER/ASSISTANT/REASONING/TOOL/TOOL_RESULT/STATUS/SYSTEM…）可以 1:1 移植。
- iOS 挂载缝隙：`SessionServe.start()` 的 `distRoot = OfficialWebRuntime.locateDist()`（hosts/ios/App/Source/SessionServe.swift:131）换成按 flavor 分派即可；auth-lite token、`/api` bridge、mux、scripted-LLM 全部复用。渲染管线 `renderIndex` 的注入行对自家客户端传空行即可（ModuleLoader 门面/启动图/phone CSS 都是官方页专用）。
- 桌面迭代环：`tools/dev-web-carrier/`（Node fixture 载体）加一个 `--client next` 模式，CSS/布局迭代不用过模拟器（0.5s 冷启动）。

## UI 设计（从 clarklevis 借什么）

**设计语言**：深海色板（navy `#06172B`、ocean `#2E6BE6`、mist `#BFD6FF`、ink `#0E131A`、paper `#F9FAFC`；紫=思考、橙=工具、琥珀=连接中/审批、绿=完成）；玻璃卡面（blur + 0.7pt 白描边 + 柔和 navy 阴影）；圆角阶 24/22/18/15/10；会话页明暗自适应（systemBackground 系），主页固定深海玻璃风。

**首页**：品牌标头 + 网关状态胶囊（在线点）+ 「新建会话」大玻璃按钮 + 会话列表（状态点：绿色脉冲=运行中、蓝色=未读；标题 + 等宽短 id + 相对时间）。

**会话页**（双区：对话 + 简易轨迹）：用户消息=右对齐 ocean 气泡（r15，34pt 内缩）；助手消息=全宽无气泡（头像+标题头，正文 markdown）；流式尾行=专用元素只做文本追加（绕开列表 reconcile），标题「正在思考/生成」；**过程组折叠**（思考=紫、工具组=橙「使用了 X、Y」、逐工具行带图标 + 等待/失败 chips + 超长输出封顶滚动视口）；markdown 渲染带 **解析缓存**（Map: 源串→块树，防重渲染重解析）；复制按钮只在用户消息和最终回答上（点击变 ✓ 1.4s）；到底按钮 + 用户拖动时暂停应用增量（rAF 合帧）；输入甲板=玻璃卡（占位文案、发送键生成中变形为停止键）。

**v1 功能面**：会话列表/新建、流式回复+思考折叠、工具卡片、markdown+缓存、发送/停止、深浅色自适应、`env(safe-area-inset-*)` 适配（WebView 拥有窗口，页面自己垫安全区）。slash 菜单/模型选择/审批卡/统计胶囊留到 v2（架构上预留）。

## 实现步骤

1. **任务卡**：`gov task new "web-client-next UI redesign" --check …`（规则 9）。
2. **客户端本体** `presentation/web-client-next/`（manifest 照 v0 schema；无构建步骤、vanilla ES modules，每个文件 ≤500 行过 code-size 门；JS 文件头 `// dsh:logging-exempt` 过 logging 门）：
   - `web/index.html` + `css/theme.css`（色板/玻璃/明暗）+ `css/chat.css`
   - `js/api.js`（POST /api 信封）、`js/mux.js`（remote.mux：journal 基线+增量、断线重连）
   - `js/timeline.js`（事件折叠 → 9 类 item）、`js/render-chat.js`（流式尾行+折叠组+复制）、`js/markdown.js`（子集渲染器+缓存）、`js/composer.js`、`js/home.js`、`js/main.js`
   - 词表落地时以 `third-party/deepseek-harness/packages/sdk` + runtime journal 产出侧为准逐个钉死。
3. **桌面迭代环**：`tools/dev-web-carrier` 加 `--client next`（serves 新客户端 + 现有 fixtures，fixtures 补工具/思考事件）； headless 截图自查视觉效果。
4. **iOS 挂载**：`gen_bundle_header.py` RESOURCES 加行 → `SpikeBundleStager` 写出 staged 树 → `SessionServe` 按 `SessionLaunchConfig.activeWebClient` 分派 distRoot 与空注入行 → scenario 切到新 id（如 `nextweb.mount`）。
5. **E2E**：`test/e2e/scenarios/nextweb-mount.json`（钉 client.selected → index.rendered → upgrade.accepted mux → session.attached → token.delta.forwarded → 会话完成，词对词）+ 跑脚本 + 提交 artifacts（logs.txt/scenario.jsonl/verdict/receipt）+ `docs/e2e-matrix.md` 加行。模拟器跑绿。
6. **文档**：`presentation/README.md` 加 v2 条目；Agent Note（Problem/Decision/Alternatives considered——它击败了「注入 CSS 给官方页换肤」和「改 v0 /ws 客户端」两条路）；`gov verify pairing` 如动到成对文档。
7. **提交流程**：分支 → commit（Angular 规范）→ PR → 等 `gates` → squash merge；最小门集用 pre-push-checks 技能选。
8. **收尾**：govrail field feedback 汇报；值得提的 issue 提交上游。

## 明确不做（本次）

- 不改 `presentation/official-web/`（D6 钉死）；不动 v0 客户端；Android/Harmony 挂载（各自硬编码点已探明，后续 PR）；Live Activity/推送类原生能力（Web 客户端做不到，记入 v2+ 与原生壳议题）。

## 风险

- mux 帧形状与 journal 词表要在实现首日从 CarrierAPIBridge + runtime 逐字段钉死（调研只到命名层面）。
- 官方座位的 scenario 证据默认仍是官方路径（E2E boot 字节不变），新客户端走 opt-in flavor，`webclient.mount`/`ui.client-swap` 不受影响。
- 无构建步骤意味着 markdown 渲染器手写子集（标题/粗斜体/行内码/围栏码/列表/引用/链接）；后续要更强的渲染再走 vendor-package 流程引 pinned 包。
