# Proposal: stop committing the iOS generated bundles — `App/Generated/` and the xcodeproj become build output

> **Status: DRAFT (amendment proposal — nothing flipped, nothing frozen, nothing
> implemented; filed for the owner to accept or reject).**
> English | [简体中文](2026-09-29-generated-bundles.zh.md)

## Motivation

The iOS host's generated bytes are committed: `hosts/ios/App/Generated/SpikeBundle.c`
+ `SpikeBundle.h` (the runtime/dsh closure embedded as C byte arrays) and
`hosts/ios/DSHSpike.xcodeproj/` (`project.pbxproj` + workspace data, regenerated
from `project.yml` by `xcodegen generate`). The decision that put them there lives
in the M1 spike-embed note
(`.agents/notes/implemented/feature/2026-09-19-ios-m1-spike-embed.md:37-39`):
*"the generated `DSHSpike.xcodeproj` is ALSO committed so CI and fresh clones
build without xcodegen"* — with the alternative "commit only `project.yml` and
generate in CI" explicitly rejected. The `closures` gate's iOS leg
(`build/check-closures.sh:41-61`) was built on top of that choice: regenerate the
bundle deterministically and demand `git diff --quiet`, so the committed copy
stays a failing-able claim (D17).

One evening of working against that copy (2026-09-29) measured what the choice
now costs:

- **6 regenerations in one evening** (the run brief's count; routine, because
  the closures gate itself regenerates on every run) **of a file that grew
  48,599,826 → 64,510,997 bytes** over the evening's landings (measured from
  the committed blobs at `f1627796` and `97f24d13`; the brief's "~50 MB" was
  the file at the start of the evening).
- **Six-figure textual churn per rewrite, measured**: the first landed rewrite
  (`f1627796 → 64889c54`) is 986,661 changed lines; the second
  (`64889c54 → 97f24d13`) is 92,024 (41,564 deleted + 50,460 added, out of
  665,411 lines). The brief's "~300k diff lines" is the same class of churn seen
  mid-evening; the exact diff it measured is not reconstructible from here.
- **One nondeterministic-drift incident** — `908c3bdd` ("the stale copy carried
  six duplicate trees from a mid-refetch walk"): a generation run that overlapped
  `ensure-dsh.sh`'s pin refetch embedded the `agent-presets`/`util` trees twice,
  and the committed copy had to be re-landed (63,647,458 → 64,468,373 bytes) to
  keep the closures gate's byte-compare meaningful at all.
- **Essentially all of the push payload**: raw blob bytes across the evening's
  range (`f1627796..97f24d13`) are 128,158,455 bundle bytes against 17,888,152
  for everything else — 87.8% measured over the whole range; a bundles-only push
  (the `908c3bdd` fix is a one-file commit) is effectively 100%. The brief's
  "99.9% of push payload" is that class.
- **An amend-ordering hazard** (the run brief's; the ledger shows its class):
  any amend after touching `runtime/dsh` now has
  a regenerate-before-amend ordering constraint, and getting it backwards ships a
  stale bundle in the amended commit — the same failure class already recorded in
  the surprise ledger (2026-09-27: a parallel session's reshuffle briefly pushed a
  stale `SpikeBundle.c`).

The `.gitattributes` change in flight on this branch (generated paths marked
`binary`/`linguist-generated`) treats the review-rendering symptom: diffs render
as `Bin` instead of six-figure line noise. The bytes still travel, still churn
the pack, and still make every runtime/dsh touch a 64 MB commit.

**And the premise has hollowed out.** The committed copy's justification was
"builds without generation". But `gen.sh`'s bundle half already runs inside every
Xcode build: the `GenerateSpikeBundle` pre-build phase executes the very same
`Tools/gen_bundle_header.py` that `gen.sh` runs (`hosts/ios/gen.sh:5-6`,
`hosts/ios/project.yml:96-135`), and `FetchIshRootfs` already stages the third
file in that directory — the untracked `ish-rootfs.tar.gz` — from a pre-build
phase (`project.yml:145-152`, `.gitignore:217`). What "fresh clone builds without
generation" still buys today is only the *project* half: no workflow installs
xcodegen, so every CI path leans on the committed `project.pbxproj`
(`dev-ios.yml:179`; `release-ios.yml:198,206,269,277`). The bundle copy buys a
first-build cache seed and feeds the gate's byte-compare — it is no longer an
input to anything, it is gate fodder with a 64 MB shipping habit.

The costs are now measured, and the one thing that used to make CI-side
generation scary — nondeterminism — was fixed tonight with proof
(see "The determinism prerequisite already landed"). That makes this the moment
to re-open the 09-22 rejection by proposal, not by silent drift.

## Proposal

Three moves, all reversible; **nothing here is executed by this document**.

1. **Stop committing the generated bytes.** Remove
   `hosts/ios/App/Generated/SpikeBundle.c` + `SpikeBundle.h` and
   `hosts/ios/DSHSpike.xcodeproj/` (`project.pbxproj`,
   `project.xcworkspace/contents.xcworkspacedata` — two files under
   `App/Generated` plus two under the xcodeproj: 4 tracked generated files
   today) from
   the index, and add both paths to `.gitignore`. `ish-rootfs.tar.gz` is already
   ignored — `App/Generated` becomes, as a whole, what it mostly is today: build
   output.
2. **Generation becomes the build's job at every consumer site.** Every consumer
   of the committed bytes already funnels into one command shape —
   `xcodebuild -project DSHSpike.xcodeproj` (enumerated in Preconditions, P2) —
   so a `gen.sh` step (vendored sources → `gen_bundle_header.py` →
   `xcodegen generate`) ahead of each site covers the surface uniformly. The
   pre-build phase keeps regenerating the bundle per build exactly as it already
   does; nothing about the app's runtime behavior changes.
3. **The `closures` gate's iOS leg flips from byte-compare to gen.sh-exits-0.**
   Today `build/check-closures.sh:41-61` regenerates the bundle into the tree and
   demands `git diff --quiet` on it. After the flip, the iOS leg's claim becomes
   *"the generator runs and succeeds on this tree"* (`gen.sh` exit 0), not *"a
   64 MB copy in the index matches"*. The android and harmony byte-compares are
   untouched (see Non-goals).

## Preconditions to verify before flipping

- **P1 — the CI workflows install xcodegen and generate before xcodebuild.**
  Verified today: **not yet true** — `grep xcodegen .github/workflows/*.yml`
  returns nothing; `dev/ios` and `release/ios` build against the committed
  project directly. This is the load-bearing gap: the flip is green only after
  both workflows gain an install + `gen.sh` step ahead of their first
  `xcodebuild`.
- **P2 — every consumer of the committed bytes goes through xcodebuild.**
  Verified today: **true**. The complete consumer census: 12
  `test/e2e/run-ios*.sh` scripts (agent-flow, device-plane, install-ui,
  live-llm, live-session, live-write, next-web-mount, official-web-mount,
  session-mock-llm, upstream-parity, upstream-suite, run-ios.sh) all invoke
  `xcodebuild build -project hosts/ios/DSHSpike.xcodeproj`; `build/build.sh:136`
  (compile stage) and `build/build.sh:112` (sync stage, already runs `gen.sh`);
  `dev-ios.yml:179`; `release-ios.yml:198,206,269,277`. The only other readers
  of the bytes are the gate being flipped (`check-closures.sh:42-59`) and the
  `dev-ios.yml:77` DerivedData cache key, which must rekey onto `project.yml` +
  the sources once the pbxproj stops being tracked.
- **P3 — a fresh `gen.sh` has its inputs.** `gen.sh:3-5` requires
  `runtime/dsh/vendor/ensure.sh` first (xcodegen needs the quickjs sources on
  disk to reference them). `dev/ios` already vendors before building
  (`dev-ios.yml:159-163`); the flipped gate's generation leg needs the same
  ordering.
- **P4 — the local raw-script path still works.** The `run-ios*.sh` scripts
  currently assume the committed project exists; each needs the `gen.sh`
  pre-step (or a shared helper) at flip time. The `build/build.sh` facade path
  is already correct (`sync ios` runs `gen.sh` before compile).
- **P5 — rollback stays one revert.** Because generation is deterministic
  (below), restoring committed bytes is always `git rm --cached` + regenerate +
  commit. The flip does not burn a bridge.

## The determinism prerequisite already landed

CI-side generation was rejected on 2026-09-22 partly because a generated tree
that drifts run-to-run turns CI red for noise. That objection was retired
tonight, with evidence: `908c3bdd` fixed the walk to be order-stable
(`Tools/gen_bundle_header.py:391,419` — `sorted(src_dir.rglob("*"))` walks) and
verified the output **byte-stable across runs (same hash twice)**, which is
exactly the property the closures gate's regen-and-diff machinery exists to
check — and which has been checked green on every gate run since. Determinism is
the precondition that makes "the bytes are reproducible from the sources" a
claim a gate can hold without keeping the bytes.

## Alternatives rejected

- **Git LFS for the bundle** — rejected: the file rewrites at ~64 MB per
  regeneration, several times per evening; LFS's storage/bandwidth quota makes
  that a recurring bill, the pointer still churns in every touching commit,
  every CI checkout needs an LFS pull step, and the history keeps its bytes
  anyway. Paying for the bytes we are trying not to ship.
- **Per-file C arrays (split `SpikeBundle.c` per input file)** — rejected: the
  pain is the bytes traveling at all, not their diff granularity; the payload
  and the churn stay, compile units multiply, and build time grows.
- **Embedded-compression trade-off (zstd the payload, decompress at staging)** —
  rejected: it shrinks the blob but does not stop the churn (every regeneration
  still rewrites a multi-MB blob), the committed bytes stay unreviewable either
  way, and it adds a decompress step to every scenario leg's staging path. A
  smaller tax is still the tax; the proposal removes the tax.

## Non-goals

- **HarmonyOS rawfile and Android assets keep their committed form.** Their
  closures are small text files whose diffs stay reviewable, their stagers
  verify in `--check` mode with no large-byte problem, and the self-contained
  APK/HAP packaging semantics (D17: "the copies are deliberate for
  self-contained APK/HAP and platform IDEs") argue for keeping them. The
  `closures` byte-compare stays for both. This proposal is scoped to the iOS
  generated bundles only.
- **No change to `runtime/dsh` content, the bundle layout, or the pre-build
  phases' behavior.** The app's runtime path is identical before and after.
